## 1. Production-parity bridge implementation

The training bridge (`ai-training/ts-bridge/selfplay.ts`) gained an explicit
**canonical mode** (`--canonical canonical-v1`):

- Forces `catPolicy = hard`, `mousePolicy = greedy`, `policyVersion = canonical-v1`.
- **Fail-fast** if `--catW` / `--mouseW` are also given (no way to smuggle a second policy).
- **Fail-fast** if `--shard N>1` (WORKER_COUNT must be 1).
- Writes `policy_manifest.json` (two-layer source fingerprint + runtime env) +
  `meta.json` + `pilot_diag.json` + `schema.json` alongside the six shard files.
- The historical mixed mode (`--catW/--mouseW/--shard`) is preserved untouched for forensic
  use only; canonical-v1 never routes through it.

### 2. Did it directly reuse computeCatAiTrajectory?

**Yes.** The canonical cat turn is `applyCatTurnCanonical(s)`, which:
1. (GamePage parity) if mouse-to-move & playing → `endTurn` to cat;
2. if not cat's turn / not playing → return as-is;
3. if `catMovesLeft <= 0` → reset to `catBaseMoves`;
4. calls **`computeCatAiTrajectory(catState)`** — the exact production engine path that runs
   ONE initial `planHardCatTurn` main search per turn and executes the principal line through
   the real engine transitions, with production fallbacks (`plan_action_invalid`,
   `plan_exhausted`, `no_hard_plan`) handled inside the engine — and takes the final state;
5. resolves turn completion exactly like `GamePage.runCatAi` (terminal / currentPlayer!=cat /
   **EARLY_TRAJECTORY_END** (moves left, no endTurn) / normal `endTurn`).

No rules were re-implemented in the bridge: `catMove`, `catPlaceTrap`, `mouseMove`,
`mouseSkill`, `endTurn`, plan validation, and fallback are all the production engine's.

### 3. Does canonical hard still do per-step unconditional re-search?

**No.** The canonical path calls `computeCatAiTrajectory` once per cat turn (ONE initial
main plan + production fallbacks inside the engine). The old per-step re-search
(`applyCatTurn` calling `catAiMove` fresh each step) is **only** in the legacy mixed mode.
