# TACTICAL_ARCHITECTURE_OPTIONS — 五条路线与唯一推荐

约束前提（本轮已核实）：

- 生产主搜索是 **100ms 主预算 / 150ms 总回合**，配置 D4，实测**完成最多 D2**；
- 真实 100ms 数据中 **48/48 组合 5/5 轮触发 deadline**，**182/240 轮总回合 >150ms**；
- Sidecar 现有实现中，仅候选枚举就可能吃掉 36–49ms，且 0 个候选被探测；
- H1 量词证明在冻结样本上从 46 节点/1ms 到 600k 节点/20s 不等；
- 以往失败：G0.3B 威胁延伸导致真实根 `completedDepth 1→0`、10/20 空计划回退；
  H1 corrected-hole 没有可证明的 100ms 战术收益；旧 H0 静态防守检查在 G6T2 上无区分力；
  旧跨回合 tempo 公式不满足真实步数契约。

**因此**：任何“加深度/加节点/加全称搜索”的方案都必须先证明它不会重演上述失败；
任何“证明”都必须与期望搜索严格分离。

---

## 1. 评估维度

对每条路线回答：

1. 它解决什么；
2. 它**不能**解决什么；
3. 是否改搜索数学 / 深度语义；
4. 是否改 CHANCE 语义；
5. 额外节点/时间；
6. 100ms 超时风险；
7. 对计划提取的影响；
8. 误证风险；
9. 可复用代码；
10. 是否实质性重复过去失败。

---

## 2. 路线 A — 在现有 Expectiminimax 上做选择性深度延伸

**形态**：对关键节点做 threat extension / 选择性加深 / 重新打开威胁排序。

| 维度 | 评估 |
|---|---|
| 解决 | 在关键局面多看半层到一层，可能改善战术信号 |
| 不能 | **不能产生任何安全性证明**；叶仍是静态评估 |
| 搜索数学 | 改：`extensionsRemaining`、TT 键、深度语义、计划提取都可能受影响 |
| CHANCE | 不改枚举，但更深的 CHANCE 期望仍不是全称安全 |
| 额外节点 | 高；关键节点往往正是分支最多的节点 |
| 100ms | **高**；当前连 D2 都常完不成，再加深只会更糟 |
| 计划提取 | 延伸层可能产生更长的 planBranches；受 `maxCatTurnPlanActions` 约束，但空计划/回退风险上升 |
| 误证风险 | 不产生证明，但“mate-like 评分”容易被误读为证明 |
| 复用 | 高（现有扩展框架） |
| 重复历史 | **是**：`hardTurnPlanner.ts:267-272` 明确记录 G0.3B 在真实 Turn5 上 `completedDepth 1→0`、`empty-plan fallback 10/20`，生产回滚为 0 credits |

**结论**：**禁止原样重启**。除非先证明“延伸只在能完成 D2 且不增加空计划”的条件下触发，
否则它就是把已知失败再跑一遍。

---

## 3. 路线 B — 根级独立量词验证层

**形态**：在主搜索之后（或并行），对根状态跑 `mouseForce / catSurvive / catForce`，
用 `seal_lib` 的 AND/OR 语义给出精确的有界结论。

| 维度 | 评估 |
|---|---|
| 解决 | 能给出真正的有界强制胜/存活；CHANCE 全分支 AND；有独立 verifier |
| 不能 | 不能保证在预算内完成；不能给无限期存活；不能替代计划级证明 |
| 搜索数学 | 不改主搜索；但需要新预算与新的结果合并规则 |
| CHANCE | 不改枚举；但语义从“期望”变成“全分支 AND”，**结果不可与期望值比较** |
| 额外节点 | 46–215,922（已证）；600,001（UNRESOLVED）；G6T2 重证总耗时 429,843ms |
| 100ms | **不可接受**：4 个根在 600k/17–20s 截断；根级 H1 不能塞进 100ms |
| 计划提取 | 若用它过滤计划，可能因根 `UNRESOLVED` 误杀本来可证的计划（G6T2） |
| 误证风险 | 内核本身低（独立 verifier）；使用层高（把 UNRESOLVED/`!mouseForce` 当安全） |
| 复用 | 高（`seal_lib.ts`、真实转移、独立 verifier） |
| 重复历史 | 与旧 H0 静态防守检查同类：根级检查在 G6T2 上无区分力；根级全称搜索还会被昂贵兄弟分支拖垮 |

**结论**：**不能作为根级在线层**。它可以作为离线 oracle / 测量工具，但不能放进 100ms 决策路径。

## 4. 路线 C — 叶评估加入时间战术特征

**形态**：在 `evaluateForCat` / corrected-hole 叶中加入黄油时机、隧道诱饵、
跨回合 tempo、gate 控制等特征。

| 维度 | 评估 |
|---|---|
| 解决 | 改善 SIGNAL，可能让浅层搜索选出更稳健的计划 |
| 不能 | **不能产生证明**；特征权重是启发式 |
| 搜索数学 | 不改深度/CHANCE；改评估器 |
| CHANCE | 不改 |
| 额外节点 | 几乎不变（除非特征计算很贵） |
| 100ms | 中：评估本身便宜，但权重变化会改变分支选择与耗时分布 |
| 计划提取 | 间接：不同叶值 → 不同 principal line → 不同计划 |
| 误证风险 | 不产生证明，但容易被包装成“安全” |
| 复用 | 高（现有 EvaluationFeatures） |
| 重复历史 | H1 corrected-hole 的 ERRATUM 结论是 `PROVEN_100MS_TACTICAL_GAIN=FALSE`，生产未授权；旧跨回合 tempo 公式不满足真实步数契约（当前 tempo 只是同状态步数差，`evaluation.ts:700-708`） |

**结论**：只能作为 **SIGNAL** 路线，不能作为本轮目标。若要做，必须先有独立测量证明
“权重变化带来可复现的计划改善且不破坏时间包络”。

## 5. 路线 D — 双通道：候选计划搜索 + 独立证明 + 反线验证

**形态**：主搜索负责候选计划；独立量词通道只验证**该计划前缀**之后的局面。
有两个子形态：

- **D-root**：在根上验证 → 等价于 B，成本不可接受；
- **D-plan（PCV）**：把猫第一回合固定为已执行计划，只验证前沿之后的鼠/猫/鼠……
  → 成本可望从“根级全称”降到“计划作用域的小 H”。

| 维度 | D-plan 评估 |
|---|---|
| 解决 | 直接对应“鼠最强反击 / 鼠强制胜线 / 可验证猫防守 / 动态黄油与隧道 / 不利随机 / 定向反证” |
| 不能 | 不能保证在预算内完成；只覆盖被验证的计划（+少量替代）；不能给无限期存活；随机边界需显式处理 |
| 搜索数学 | **不改主搜索**；新增一个计划作用域的量词通道 |
| CHANCE | 不改枚举；通道内用 AND，与主搜索的期望**分开报告** |
| 额外节点 | 前沿 H0 已知 18 节点（G1T3）；G6T2 根 H0 116 节点；前沿 H1 已知 179 节点（G1T3），但 DRRR 子树有 117k leaves |
| 100ms | **中**：必须从总回合预算中**预留**一小片（例如 20–30ms），不能假设 Sidecar 之后还有空余 |
| 计划提取 | 强绑定：只验证 `baselinePlan`；Sidecar/Guard 改计划 → 证明失效 |
| 误证风险 | 可控：独立 verifier + 四级证据阶梯 + cap→UNRESOLVED；风险在“把 false 当 safe” |
| 复用 | 高：`seal_lib`、`preparedActions`、真实 engine 回放、现有 deadline 机制 |
| 重复历史 | **不重复**，前提是：计划作用域、小 H、预留预算、状态分级；若退回根级全称或无限加深，就重复 B/A 的失败 |

**D-plan 的子能力映射**：

| 期望能力 | D-plan 的对应 |
|---|---|
| 识别鼠最强反击 | 前沿 `mouseForce(H0)` 的 true 给出显式鼠策略；false 只说明“H0 内没有强制胜” |
| 尽早发现鼠强制胜线 | `mouseForce(H0)` 为 true 时立即得到有界证明 |
| 找到可验证猫防守 | 前沿 `catSurvive(H0/H1)` 为 true 且 verifier PROVEN |
| 识别猫强制将死 | `catForce` 可选（成本更高，默认不做） |
| 动态黄油/隧道诱饵 | 使用真实引擎转移，天然覆盖；成本是问题 |
| 不利随机结果 | CHANCE 全分支 AND，不遗漏坏 outcome |
| 定向反证关键候选 | 只对 baselinePlan（+≤2 个等值替代）做定向验证，不枚举 6 个 legacy 计划 |

## 8. 推荐：D-plan（PCV），且先做只读测量

### 8.1 为什么不选 A/B/C

- A 已经被真实根证伪：加深会把 `completedDepth` 打回 0，触发空计划回退；当前连 D2 都不稳。
- B 的根级 H1 实测 600k/17–20s；根级 H0 虽便宜，但在 G6T2 上没有区分力，且会被兄弟分支拖垮。
- C 只能产生 SIGNAL；H1 的 ERRATUM 已经给出 `PROVEN_100MS_TACTICAL_GAIN=FALSE`。

### 8.2 PCV 的精确形态（下一轮测量原型，不接线）

```text
[主搜索，100ms 不变]
   → 实际选中的最终计划（P5 中为 finalPlan；未覆盖时等于 baselinePlan）
   → 真实规则回放到 frontier（鼠行动；记录 stateKey/预算/幽灵/陷阱/隧道）
   → [预留 ≤25ms 的 PCV 通道]
       1) mouseForce(H0), cap N1, wall W1
            true + 独立 verifier PROVEN  → REFUTED（鼠强制胜，TACTICAL_PROOF）
            false / cap / verifier 失败 → UNKNOWN
       2) 若仍有预算：catSurvive(H0), cap N2, wall W2
            true + verifier PROVEN      → SURVIVES_WITHIN_H0（TACTICAL_PROOF）
            cap / null                  → UNKNOWN
   → [决策保持主搜索结果；PCV 不直接改计划，只记录证据]
```

**候选来源**：只取**实际选中的最终计划**（P5 中为 `finalPlan`；生产接线时以执行计划为准）；
可选地取同一次 completed iteration 的等值主变首步，最多 2 个替代计划，由 `planBranches` 走出。
**不**重新枚举 6 个 legacy 全回合计划。

**为什么先只读**：

- 不知道前沿 H0 的真实成本分布；
- 不知道随机边界出现的频率；
- 不知道 PCV 会不会把 155.6ms 的观测包络推得更高；
- 不知道 `REFUTED` 在 48 组合中会出现多少次、是否与根分类一致。

### 8.3 四级证据阶梯（实现时必须写死）

| 级别 | 定义 | 可以做什么 | 不可以做什么 |
|---|---|---|---|
| `TACTICAL_SIGNAL` | 期望值、静态特征、`NO_REFUTATION_FOUND`、`CHANCE_MIXED`、`INCOMPLETE`、`mouseForce=false` | 排序、提示、调试 | 安全、胜率、证书 |
| `TACTICAL_CANDIDATE` | 合法、完整、已做有界搜索但未完成全称验证的计划 | 候选比较 | 安全证明 |
| `TACTICAL_PROOF` | cap 未命中 + 终端/horizon 明确 + 独立 verifier PROVEN + 绑定计划前缀/stateKey | `mouseForce=true`、`catSurvive=true`（H 内）、`catForce=true` | 无限期存活、根级全称 |
| `TACTICAL_DECISION` | 实际执行的计划 | 执行、记录、回放 | 把 SIGNAL/CANDIDATE 升级为 PROOF |

**硬纪律**：

- `NO_REFUTATION_FOUND` 永远不是 safe；
- `!mouseForce` 永远不是 `catSurvive`；
- `mate=null` 永远不是“和棋”；
- `UNRESOLVED` 永远不是 PASS；
- cap/deadline 命中一律 UNKNOWN。

### 8.4 PCV 不能做什么（必须写进报告）

- 不能给根级全称结论；
- 不能给无限期存活；
- 不能覆盖未验证的计划（除非另做验证）；
- 不能在随机边界未纳入 AND 时声称“无条件安全”；
- 不能把期望值搜索与全称证明混为一个分数。

## 9. 决策链约束（来自 Phase 4）

1. 证书绑定**真实回放的执行计划**，不绑定 `bestAction`；G5T1/E1 是明确反例。
2. `baselinePlan = search.catTurnPlan`；Sidecar/Guard 改计划后，旧证书失效。
3. 执行层逐步校验；`SEARCH_FALLBACK` / `plan_exhausted` / `plan_action_invalid` 发生后，
   实际轨迹 ≠ 被证明前缀，证书立即失效。
4. 根分类与计划前缀证书作用域不同；不能互相替代（G6T2）。
5. PCV 若要影响决策，只能在“基线被 PROVEN 反驳且存在干净替代”时建议替换；
   不得仅凭 SIGNAL 改变计划。

## 10. 下一轮的唯一目标（不是生产接线）

**PPC-T1-PCV-01：计划作用域反线验证的只读测量原型。**

- 冻结 24 根 × 2 叶臂 × 5 轮 = 48 组合；
- 主搜索配置完全不变；
- 只读回放 `baselinePlan`，在 frontier 跑 `mouseForce(H0)`；预算允许再跑 `catSurvive(H0)`；
- 记录每个结果的类别、节点、chance 节点/outcome、耗时、截断、verifier、stateKey；
- 与既有根分类/证书做**作用域对齐**比较；
- 不修改生产源码，不改变主计划，不运行 self-play / 全回归 / 大 benchmark。

GO/NO-GO 与所有阈值见 `NEXT_STAGE_PREREGISTRATION.json`。

**如果 G2（覆盖）失败**：结论是 `PCV-NO-GO`，下一步只允许改候选来源/预算分配设计，
不允许直接扩大预算或退回根级全称搜索。

---

## 11. 结论

- **唯一推荐**：D-plan（PCV），计划作用域、单边、小 H、预留预算、四级证据分级。
- **明确不推荐**：A（重演 G0.3B）、B（根级全称不可承受）、C（只能给信号，且 H1 无收益）。
- **本轮不实现**：只交付架构与预注册；生产接线 NO-GO。
- **成功标准不是“赢更多”**，而是“在 100ms/150ms 约束下，能否对已执行计划给出/否证
  一个有界战术结论，并且不产生假证明、不破坏计划与时间包络”。
