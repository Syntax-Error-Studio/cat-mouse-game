## 2 数学模型：最终形式

计数口径（`drivers/lib/arms.ts` 的 `countingRules` 只包住五个内核，已由门禁第 7 项核对）：

- **模拟器调用** = 调用 `simulateSearchAction`；
- **内核调用** = 进入 `mouseStep` / `catMove` / `mouseSkill` / `catPlaceTrap` / `chooseTunnelExit` 之一；
- 二者 1:1，唯一例外是 RULE-A（`applyNoMoveLoss` 已判定当前行动方无合法空间移动）：模拟器提前返回，
  产生 1 次模拟器调用、**0 次内核调用**；
- `endTurn`、`enumerateButterSpawns`、`buildButterChance` / 边界 CHANCE 构造**不计入**，且两臂相同。

记号：`N` 枚举候选数，`E` 免验证候选数（隧道出口），`V = N − E`，`k` 最终合法数。

```
C_L(s) = V + 1[k ≥ 2]·k + 1[k ≥ 1]      （合法性 + 引导 + 执行）
C_P(s) = N = V + E                       （每候选一次，转移保留）
```

四类边界（均已在正文与图 1 中逐条写明）：

| 情形 | 两遍式 | 复用 | 说明 |
|---|---|---|---|
| k = 0 | N | N | 枚举后结束本步，不进入引导与执行 |
| k = 1 | N + 1 | N | 引导扫描短路，两臂都不抽随机数 |
| k ≥ 2, E = 0 | N + k + 1 | N | 节省 `(k+1)/(N+k+1)` |
| 隧道（V = 0, E = k） | k + 1 | k | 出口免验证，但仍需引导与执行 |

节省比例的精确界（`E = 0`）：`k ≥ 2` 时最大值在 `N = k` 处取 `(k+1)/(2k+1)`，**严格大于 1/2**，
随 `k` 增大从上方趋近 `1/2`；`k = 1` 时为 `1/(N+1)`（`N = 1` 恰为 1/2）；`k = 0` 时为 0。
因此不存在「最多省一半」这种与候选规模无关的上限——该表述已删除。

**不做的事**：不把合计比值 0.5206 反解成任何局面形态的占比。原因是合计值是各步比值按 `C_L` 的加权
平均，权重未知，反解不可逆。合计计数中树内扩张部分两臂逐行相同，但本轮**未**把两部分分开计数，
故正文不对「采样步单独降幅」给数值，47.94% 只作为内核调用总量的下降幅度陈述。

## 3 语义描述

- 复用对象是两类后继：确定性转移的单个后继状态，以及确定构造的 CHANCE 结果集 `(o_i, w_i)` 与其原顺序。
- 抽样前三道校验：结果集非空、每个权重有限且严格为正、`|Σw − 1| ≤ 1e-9`（取绝对值，已核对
  `proto/chance.ts` 的 `MASS_TOL` 与 `Math.abs(sum - 1)`）。
- 「同一后继状态对象」已全部替换为「后继状态的结构与语义逐字段一致」（表 1、图 1、引理 2 一致）。
- §3.4 新增边界段：三条引理是**代码级论证**（逐行对应控制流），96,000 次摘要比对是**冻结语料上的
  有限检验**；两者都不构成「任意合法局面必然一致」的全称证明，正文已明确声明未做该证明。

  故不给出该占比，也不据此排除任何一类成本」。

### 4.1 `rolloutPreparedSteps` 与 `rolloutSteps` 的差值

按字段来源核实，而非由差值反推：

1. `rolloutPreparedSteps` 在采样步内自增（`uctPrepared.ts` 采样步循环内），被截止打断的采样中
   已走过的步也计入；
2. `rolloutSteps` 只在采样**完成**后并入（`run()` 中 `this.rolloutSteps += sim.rolloutSteps` 位于
   `!sim.completed` 分支之后），中断采样不计；
3. 回退步为 0（`impureFallbacks` 恒 0），因此完成统计中不含旧路径步数。

故差值 = 中断采样中已走过的步数（实测约 5.0 步/调用）。正文按此表述，并给出上述三条依据。

## 6 指标表与生成门

`COMPETITION_METRICS_TABLE.md` 为 3 列 × 15 行数据，由生成器直接写出（非粘贴转换）。门禁会重新解析
该文件并与内存中的表格**逐格比对**，列数、分隔行、行数、单元格文本任一不符即 FAIL。

`scripts/makeTechnicalInsert.mjs` 的 37 项检查分七类：

1. 未插值残留（`${`、NaN、undefined、`[object Object]`、游离字符串拼接）；
2. 数值一致性：Phase 1 汇总字段 = 逐单元求和、Phase 2 均值 = 逐条求和 ÷ 480、17 个关键数值必须同时
   出现在正文与指标表；
3. 公式一致性：直接读源码核对计数口径（`bump()` 恰 5 处）、`MASS_TOL=1e-9`、两臂树内扩张各 1 处、
   两遍式 k=0 早退 / k=1 短路 / 选中再执行、复用单批构建、隧道是唯一免验证分支；
4. LaTeX 安全：剥掉全部 `\cmd` 后仍能匹配到 `ge`/`le`/`cdot` 等残骸即判 FAIL（本轮真实捕获过一次
   `\ge` 被 JS 转义吞成 `ge` 的缺陷）；
5. 表格结构：表格数量、每行列数、分隔行合法性、逐格比对；
6. 图表：中文标签、`<text>` 字号下限 ≥ 13、空文本节点、边界说明、已删除论断的缺席；
7. 可重复性：另起一个进程重新生成，比对正文与（归一化时间戳后的）指标表摘要；时间戳本身不参与比较，
   且被检查为「恰好一行、位于表格之外」。
