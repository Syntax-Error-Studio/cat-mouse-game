**PRIMARY_CLASS = MIXED_BY_ROOT**：同一 100ms production 主搜索在两个 mechanism-control root 上呈现**不同**的信息边界——

- **G8T10 = REPRESENTATION_CONFIRMED**（`H1_ORACLE_RANK_INVERSION=TRUE`）：production 100ms 只完成 D1（选 RUUU，IMMEDIATE BAD）；但**固定 D2/D3 完成后，同一 frozen H1 自选 RRRD（STRUCTURAL BAD）而非 SAFE 的 DURR**。per-plan H1 D2 值：全部 R 线（RUUU/RRRL/RRRD/RUUR）= −1233.21（METHOD_A 全 BAD）> D 线（DURU/LUUU/**DURR**）= −1377.95（DURR=唯一 SAFE）。**搜索已到达完整 frontier，H1 把 BAD 计划排在唯一 SAFE 计划之上**——这不是 horizon（加深不修），是 leaf-value rank inversion（与 1.9E authority 值逐位一致：−1233.2105263157896 / −1377.9473684210527）。

| depth | selected plan | value | METHOD_A | 含义 |

per-plan H1 D2（root MAX 每首动作线的完整 D2 值）：**R 线全 −1233.21（BAD）> D 线全 −1377.95（DURR=SAFE）** → `H1_ORACLE_RANK_INVERSION=TRUE`；`SAFE_FRONTIER_REACHED=TRUE`（D 线值已被搜索计算）、`SAFE_FRONTIER_MISRANKED=TRUE`；`ORACLE_BAD_REACHED=TRUE`（RRRD 被搜到并被选）。

**§15 结论**：RRRD structural-loss frontier 被搜索到、DURR SAFE frontier 也被搜索到（−1377.95 已出现在 rootValues）、值差形成于 **leaf value（H1 ordering）层**，非 depth / MIN selection / timeout。

**G8T10_BOUNDARY_CLASS = REPRESENTATION_CONFIRMED**（HORIZON_ADDITIONAL=FALSE：D2/D3 均不修）。

| depth | selected plan | value | METHOD_A | 含义 |

## 8. 结论与含义（只诊断，不提 production fix）

1. **G8T10 的 production information boundary 不在 depth**：100ms 只完成 D1，但即使 D2/D3 完成，frozen H1 仍选 METHOD_A BAD 计划。1.9E 的 `LEAF_VALUE_REPRESENTATION` 结论在真实 production 搜索结构中**直接重现**（per-plan H1 排序 R 线 > D 线 = BAD > SAFE）。**H1 leaf 对"结构性败线的 R 线 vs 唯一 SAFE 的 DURR"排序反转是 G8T10 的根因。**
2. **G1T9 的 production information boundary 就是 depth**：同一 H1 完成 D2 即自选 SAFE DRDD；production 100ms 完成 D1 后 D2 超时。**leaf 排序正确，缺的是 completed depth。**（§17 表明 evaluator 成本主导 D2 不可完成性——但那是诊断观察，不构成生产改动建议。）
3. 两 root 合起来证实：**生产 100ms 的信息边界是"混合"的**——G8T10 是 leaf representation 缺陷、G1T9 是 search efficiency/horizon 缺陷。任何单一方向（只加深度 or 只换 leaf）都无法同时修复两个 root。
4. 按 §18/§30：不因 1.9G/1.9J 的 METHOD_A 投影加速而推断 production 应采用同方案（本轮无 duplicate-state/alloc 归因证据支持 transplant）；不基于本报告直接修改 AI。
