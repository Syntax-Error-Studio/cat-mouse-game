## 1. holeControl sign bug 正式确认

读 `src/game/ai/evaluation.ts`：
- L569：`holeControlMargin = catHoleGateDistance - mouseHoleGateDistance`
- L679：`holeControl = clamp(holeControlMargin/boardSize) * weights.holeControl`

**HOLE_CONTROL_SIGN_BUG = TRUE**
- 当猫更靠近 gate（catHoleGateDistance 更小）时，margin 更负 → holeControl 更负 → **惩罚猫靠近洞门**，与注释意图（"cat guards gates earlier = good"）相反。
- 正确 intended semantics：`correctMargin = mouseHoleGateDistance - catHoleGateDistance`（猫更近 → 正 → 对猫好）；保留单边可达：cat-can/mouse-cannot → +boardSize，mouse-can/cat-cannot → −boardSize。
- **本轮不改 src/evaluation.ts**。`PRODUCTION_HOLE_CONTROL_FIX = CANDIDATE_ONLY`（改 evaluateForCat 会影响 baseline/Hybrid/refutation/历史 benchmark，必须 independent confirmation 后才能进 production）。

### 关键归因（§7）
- **Q1. HOLE_FIX_ONLY 是否 G19_TOP1_SAFE = PASS？** **NO**（safeRanks=[3,10]）。符号反转修复本身不够。
- **Q2. C2_FIXED 是否提供独立增益？** 部分：把 safe 从 rank #3 提到 rank #2（w≥0.10），但未达 #1。
- **Q3. H1C2 是否明显优于两者单独？** safeRanks=[2,11] vs H1 的 [3,10] / C2 的 [2,18]——**改善了 RRRD（11→?），但 UUDD 仍 rank #2**，未达 top1。

### 根本原因（f11_diff 探针）
safe `UUDD`（cat(5,3)）与 unsafe `RDUL`（cat(5,3)）**猫位置相同**，仅差一个 box：UUDD 有 box at (6,4)，RDUL 有 box at (7,4)。这个 box 差改变 `mouseWinRouteDistance`：UUDD=13（安全，鼠距胜更远），RDUL=10（不安全，鼠距胜更近）。
- **区分信号是 box-push 对 mouseWinRouteDistance 的影响**——这正是 **C1 route-urgency feature（mouseWinRouteDistance）** 所编码的，但 **F1.1 的 arm 集合（C0/H1/C2/H1C2，禁新 feature）刻意排除了 C1**。
- BUTTER_GUARD_MARGIN 和 HOLE_FIX 都无法区分同猫位置下的一格 box 差 → 无法达到 top1。
