## 2-4. A. 修复真实 execution memory（classifyExecutedCatTurn）

### 新增纯 helper（progressGuard.ts）

`classifyExecutedCatTurn(root, finalExecState, executedPlanLabel, matchedPlan)`：
- 直接比较 **root**（cat-turn 起点 state）vs **finalExecState**（真实最后执行 step 的 state）计算：
  - `fullTurnConsumed` = finalExecState 仍 Playing ∧ currentPlayer=Cat ∧ catMovesLeft≤0
  - `closedLoop` = fullTurnConsumed ∧ endCat==startCat
  - `HAS_STRATEGIC_PROGRESS`（A-I 复用 analyzeProgress(root, finalExecState)）
  - `LoopSignature` = (catStart=root.catPosition, catEnd=finalExecState.catPosition, plan=executedPlanLabel, boxHash, trap)
- **无二次模拟**（不从 finalExecState 重新 replay plan）。
- `matchedPlan=false`（SEARCH_FALLBACK / plan_exhausted / plan_action_invalid / trajectory fallback）→ 全 false + signature=null。

### engine.ts computeCatAiTrajectory 修复

- 捕获 `progressGuardExecutionRoot = current`（planHardCatTurn 前的真实 cat-turn root）。
- 执行后：`classifyExecutedCatTurn(progressGuardExecutionRoot, finalExecState, finalPlanLabel, executedClean)` → 写 memory 到 last step state（与 hardSearchHistory 同模式）。
- **matchedPlan 唯一计算**：`executedClean = !steps.some(st => SEARCH_FALLBACK 标记)` —— 唯一真值源。
- **STALE_MEMORY_REENABLE（§16）**：guard OFF 时任何新 Hard cat execution 使既有 memory 失效（`makeProgressGuardMemoryInvalid`），杜绝 re-enable 后把过回合误当"上一猫回合"。

### 证据

- **REAL_TRAJECTORY_MEMORY_WRITE = PASS**：T14 root 真实执行 ULDR（rules.catMove 生产级逐-步转换）→ fullTurnConsumed=true、closedLoop=true、noProgressLoop=true、signature.plan=ULDR、memory.previousNoProgressLoop=true、memory.mouseTurnObserved=false（P24b + f2b16r/memory_execution.json）。
- **REAL_MOUSE_BOUNDARY_MEMORY_ARM = PASS**：真实 endTurn(Cat→Mouse) → mouseTurnObserved 仍 false；真实 endTurn(Mouse→Cat) → true（P24b 尾段 + memory_execution.json catToMouseArmed=false / mouseToCatArmed=true）。

## 5-9. B/C. total deadline 起点 + no-trigger fast path（hardTurnPlanner.ts）

### 绝对 total deadline（§7/§8）

- `planHardCatTurn` 在 `t0`（plannerStart）计算一次 `absoluteTotalDeadlineMs = t0 + totalBudgetMs`（totalBudgetMs 与 refutation 共享语义：refutation ON → 150ms，OFF → timeBudgetMs）。
- `runProgressGuard` 接收 `absoluteTotalDeadlineMs`，**不再从 guardStart 重算**。
- §8 语义：planner start=0、main=100ms、total=150ms → guard 最多剩 50ms；guard start≥150ms → 立即 `abortReason='deadline'`、`rescueApplied=false`、保持原 plan。

### No-trigger fast path（§10/§11）

- 在 eligibility + refutation gate 之后、**任何 current-plan replay 之前**插入 cheap previous-memory gate：
  `memory==null || previousNoProgressLoop==false || previousSignature==null || mouseTurnObserved==false` → 立即 `abortReason='no_previous_repeat_context'`（零 replay/enumerate/probe）。
- 这是触发语义的**精确短路**（不可能改变 trigger 结果），只是避免无谓的昂贵工作。

### P20 deadline 回归真测

用 fake monotonic clock：`now()=151, totalBudgetMs=150, absoluteTotalDeadlineMs=150` → guard 立即 abort：`rescueApplied=false, abortReason='deadline'`，final plan 保持 original。**ABSOLUTE_TOTAL_DEADLINE = PASS**、**DEADLINE_FAIL_CLOSED = PASS**。
