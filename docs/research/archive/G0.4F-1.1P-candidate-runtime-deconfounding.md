目的：F1.1R 的 HOLE_FIX_PLUS_ROUTE_0.05 prototype 有重复 feature extraction（h1HoleFixHybrid 与 prePickupRouteUrgency 各 buildContext 一次），microbench 1.38x CURRENT，可能混杂了 F1.1R smoke delta=-0.0408。本轮只消除该重复。

---

## 1. Optimized candidate（单次 evaluateForCatDetailed）

`h1r1EvaluateOptimized(state)`（ai-training/f11p/f11p_candidate.ts）只调用一次 `evaluateForCatDetailed`，从同一 breakdown 取得全部：
- `features.mouseWinRouteDistance`（route）
- `features.catHoleGateDistance` / `features.mouseHoleGateDistance`（holeControl）
- `contributions.holeControl`（old）
- `total`

A. `correctedHoleControl`：语义与 F1.1 `correctedEvaluateForCat` 完全相同（both-reachable → `clamp((mouseDist−catDist)/boardSize)*500`；单边 → old 不变）。
B. `PRE_PICKUP_ROUTE_URGENCY`：语义与 F1.1R `prePickupRouteUrgency` 完全相同（carrying→0，null→+1，否则 `-(1-clamp(route/(2*boardSize)))`）。
C. `candidate = 0.5*tanh(correctedEval/S) + 0.5*productionValueNet(state) + 0.05*routeContribution`，其中 `correctedEval = total − oldHoleControl + correctedHoleControl`。

## 2. Fail-closed

任何 nonfinite / exception → 回退 `CURRENT_HYBRID`（`hybridEvaluateForCat`）。正常 canonical state 数值不变。

## 4. BFS / evaluator call accounting（§4）

用 `resetEvaluationCalls` / `getEvaluationCalls` / `getMouseBfsCalls` / `getCatBfsCalls` / `getCarryMouseBfsCalls`（未改 production counters）：

| 每 leaf | eval | mouseBFS | catBFS | carryBFS |
|---|---|---|---|---|
| CURRENT | 1 | 1 | 1 | 1 |
| OLD_H1R1 | 1 | **2** | **2** | **2** |
| OPT_H1R1 | 1 | **1** | **1** | **1** |

**OLD 每 leaf 重复构建 2 次完整 evaluation context（2×BFS）；OPT 与 CURRENT 相同（1 次 BFS）**——证明优化已消除重复构造。

## 7. 重跑同一 200 smoke（§7，idx 300..499）

```
SMOKE_N = 200 (bothResolved 196)
CURRENT_CAT_WIN_RATE = 0.7959 (156/196)
OPT_CANDIDATE_CAT_WIN_RATE = 0.8061 (158/196)
DELTA = +0.0102
CURRENT_ONLY_CAT_WIN = 9
CANDIDATE_ONLY_CAT_WIN = 11
```
诊断（两 arm）：
| | meanNodes/catTurn | meanElapsed | fallback | completedDepth {0,1,2,3,4} |
|---|---|---|---|---|
| CURRENT | 1264.2 | 479.9ms | 21 | {21,536,184,7,3} |
| OPT | 1390.7 | 518.7ms | 17 | {17,580,201,10,5} |

OPT 略深（d1/d2/d3/d4 更多）、fallback 更少（17 vs 21），nodes/elapsed 略高（约 10%）。

**注意**：CURRENT 在该 run = 0.7959，旧 F1.1R smoke 的 CURRENT = 0.8061——两次 CURRENT 有 ~0.01 差异，这是 deadline-jitter（100ms wall-clock 非确定性，G0.4B-0 已记录）所致，非算法变化。

## 8. Latency confound 解释（§8）

```
F11R_SMOKE_WAS_LATENCY_CONFOUNDED = TRUE
```
- OLD smoke delta = **−0.0408**（candidate 1.38x 慢，100ms budget 内 leaf 拖慢搜索）。
- NEW optimized smoke delta = **+0.0102**（candidate 1.01x，无延迟惩罚）。
- 去混杂后 delta 由 −0.0408 → +0.0102（+0.051 翻转），方向由负转正。考虑到 CURRENT 本身 run-to-run ~0.01 抖动，去混杂显著消除了 latency 惩罚，candidate 现在 ≥ current。

## 9. 最终判定（§9/§10）

```
SEMANTIC_PARITY = PASS
MAX_ABS_ERROR = 0.000e+0
CURRENT_US = 82.6
OLD_CANDIDATE_US = 140.9
OPT_CANDIDATE_US = 83.2
OPT_PERF_RATIO = 1.01
G19_TOP1_SAFE = PASS
G17_SAFE_OVER_UNSAFE = PASS
G4_ORDERING = PASS

OPT_CANDIDATE_CAT_WIN_RATE = 0.8061
DELTA = +0.0102
CURRENT_ONLY_CAT_WIN = 9
CANDIDATE_ONLY_CAT_WIN = 11
F11R_SMOKE_WAS_LATENCY_CONFOUNDED = TRUE
F11P_RESULT = READY_FOR_INDEPENDENT_HOLDOUT
PRODUCTION_CHANGE = NOT_AUTHORIZED
TRAINING = NOT_AUTHORIZED
```

**F11P_RESULT = READY_FOR_INDEPENDENT_HOLDOUT**（全部 gate 满足）：
- SEMANTIC_PARITY PASS（0 error）；
- G19/G17/G4 PASS；
- OPT_PERF_RATIO 1.01 ≤ 1.25；
- optimized smoke delta +0.0102 ≥ −0.05。

**CANDIDATE_UNTOUCHED_HOLDOUT = 500..1999（n=1500）**——本轮禁止读取 idx 500..1999 做 candidate selection，它们保留给 G0.4F-1.2；绝不能把 300..499 当 independent holdout。
