## 2. 架构

```
Exact minimax (完全不变)
    ↓
Equal-primary action graph (新增: 非权威 metadata)
    ↓
Context-aware plan extractor (新增: post-search DP)
    ↓
catTurnPlan
```

### 搜索阶段
- `searchActions()` 中 cat MAX node 在 root cat turn 内，lazy 收集所有 primary-equal actions
- **零 allocation 在无 tie 时**（`firstEqualAction` 单值 → `equalActionsList` 仅在首次 tie 时分配）
- 不参与 alpha-beta / compareSearchScore / TT / move ordering
- 搜索选择恢复为 **纯 stable-order**（R1 sidecar 已完全移除）

### Graph identity
- `stateKey + \x00 + depthTurns`（搜索 context-aware）
- 不含 prefix direction（prefix 只属于 extraction）
- per-search / per-iteration，incomplete iteration 丢弃

### Plan extraction
- `extractBestCatTurnPlan(root, rules, graph, planBranches)`
- 递归 DP，memo key = `(graphKey, prevCatStepKey)`
- 只使用 `simulateSearchAction`（不调用 search/evaluate）
- 最低 reversal 优先；tie → stable order
- fallback: graph miss → planBranches single-action walk

## 7. R2 scope: reversal-only

原设计考虑：reversal → revisit → uniqueProgress → boundaryEval

实际 profiling 发现 revisit/uniqueProgress/boundaryEval 在 interior hot path 会产生明显性能成本。

R2 production scope 收窄为：**ONLY immediateReversalCount**

原因：这是目前有 exact evidence 的最小行为问题，并且可以 O(1) incremental 维护。

revisit / uniqueProgress / boundaryEval：**deferred / not justified by current evidence**。
