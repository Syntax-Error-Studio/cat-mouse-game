## 2. (3,5) vs (3,7) — structural explanation of the flip

Mouse is carrying butter at (4,7); the goal corridor is fixed. What changes
when the cat stands at (3,7) instead of (3,5):

- **Corridor entry cell (4,7)** (mouse's own start cell) and the first step
  (5,7) are reachable by the cat in **1 step (D)** from (3,7), but in **3 BFS
  steps** from (3,5) (obstacle detour: row-3 path to column 7 is blocked, actual
  BFS = 3).
- The critical mouse move is `D→D→R` (3 carrying steps) to (6,8); from (6,8)
  the hole (7,8) is 1 step away — this is *why* (3,5)/(6,8) is FORCED_LOSS.
- From (3,7) the cat is at column 7 — **same column as the corridor
  (4,7)→(5,7)→(6,7)** — so the cat controls the corridor axis before the mouse
  can advance; every mouse response lands on a next-cat boundary where the cat
  retains an exact non-mate action (G0.3P: 24/24 NOT_FORCED, incl. the same
  (6,8) square which is NOT_FORCED with cat at (3,7)).
- No box/pile/tunnel difference between the two states (corridor identical,
  tunnelReach=false both). The trap IS different: production's new trap at the
  (~(2,4)-ish) position is closer to the mouse (trapDist 5 vs 8) — the *only*
  non-geometric difference, and it favors the BAD plan in the static metric.

**Conclusion:** the flip is a pure **cat-to-corridor (interception) distance
effect** — 3 vs 1 BFS steps. No maze/tunnel/trap mechanism distinguishes them
structurally except the trap's static metric.

**Diagnosis (§5):** the failure is NOT an evaluator misranking at fixed depth

has real content** (a boundary-exact follow-through would find it), but the
trigger must be a cheap *geometric* signal, since value-based rankings can't.

## 6. Why the old G0.3B classifier missed G4 (§9)

`classifyGoalThreat` keys ONLY on `mouseHasButter` + `mouseCarryingDistanceToHole`:

- G4 T2 root: butter=true, winRoute=4 → `near` (threshold carryingMoves×2=6).
- BAD mouse root (3,5): winRoute=4 → `near`.
- GOOD mouse root (3,7): winRoute=4 → `near` (**identical** — the winner-finding
  signal `catToCorridor=1` is not in the classifier's input space at all).

The classifier has **no cat-position term** (it never reads the cat's geometry
relative to the corridor), so it cannot distinguish the two mouse roots; and
its selective-extension trigger fired only on `critical` (winRoute ≤ 3), which
never occurs here. The new signal is **not** a rename of the old classifier:
G0.3B threat = pure mouse-goal urgency; G0.3Q candidates = cat↔corridor
interception, a disjoint input space. (G0.3B already FAILED production
selective extension on real Turn 4/5 for budget reasons — G0.3B-threat-aware-search.md
§3/§0: `maxThreatExtensions=0`.)

## 7. Verdict

**`SIGNAL_WORTH_PROTOTYPING = NO`** (as specified in §10 — do not force a YES).

Supporting facts:
1. G4 alone is decisive: the escape root flips via **cat-to-corridor BFS 3→1**
   (margin −1→−3), the corridor is identical, no box/tunnel mechanism differs —
   the current evaluator **reverses** the ordering (BAD +46.05 vs GOOD −416.45)
   because its Voronoi/trap/hole terms punish corridor-hugging; so this is
   **missing-information, not under-weighting** (§4 answered).
2. But the cleanest single-variable candidate (A: `catToCorridor` margin)
   **fails the G2/G5 direction gate** — anti-correlated there — so it is not
   generalizable as-is. A refined *corridor-axis interception* variant is a
   plausible prototype hypothesis but is **not yet validated** (would need an
   enumerative G2/G5 geometry test first).
3. Depth trace proves d1/d2/d3 **cannot** separate the lines by value (all tie
   by d2/d3 at −1032/−1123; even an extra whole turn from the mouse roots fails,
   d2 −1250 vs −1246) — so the *only* discriminator found is boundary-exact
   proof (G0.3P), which is the proof itself, not a cheap signal. Selective
   deepening has genuine potential (the information exists a full-window ahead),
   but **no cheap, stable, rule-correct, generalizing trigger was found this
   phase**.

Next (NOT this phase): prototype the corridor-axis interception variant, test it
enumeratively on G2/G5 roots + a held-out corpus, and only then consider move
ordering / selective extension allocation. No eval weight changes, no pruning,
no chance approximation — per §8/§11.

No production changes. No commits.
