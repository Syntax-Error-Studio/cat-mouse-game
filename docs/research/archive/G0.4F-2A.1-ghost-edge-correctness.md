修复两个已确认问题：
1. no-candidate / insufficient-candidate 时 replacement 不再永久丢失（引入 placement debt）；
2. ghost 与 Box/Trap 同格时作为真正的底层 marker（UI layering 修正）。

---

## 1. Replacement 永不丢失（§0/§1/§3/§4）

引入 `pendingButterPlacementDebt: number`（语义：尚欠多少个一对一 replacement，暂无合法 announce 位置）：
- **pickup 无候选**：`pendingButterPlacementDebt += 1`（真实 `mouseMove`；搜索 `buildButterChance` 返回 debt+1 的确定性 outcome）。
- **auto-pick replacement 无候选**：debt += 1（boundary resolve 时）。
- **reroll 无候选**：debt += 1。
- **已成功生成 ghost**：对应 debt 消耗。
- 不使用 sentinel 坐标；`debt` 是明确数值状态。

正常 pickup（candidate ≥ 1）仍**立即随机显示 ghost**（行为完全不变，§4）；只有 candidate=0 才进 debt。

## 2. debt 重试（§3/§5）

每次 CAT→MOUSE boundary：完成现有 ghost resolution 后，若 debt > 0：
- 用当前合法候选集尽可能把 debt 转成 visible ghost；
- debt=3 candidates=2 → 生成 2 个 ghost + debt 保留 1；
- 新生成的 ghost **本 boundary 不实体化**（只是 announce，需再经历完整猫回合）；
- candidates=0 → debt 原样保留，下次 boundary 再试。

## 3. 真实与搜索一致性（§5/§6/§7/§8/§9）

**真实端**（engine.endTurn）：while 循环顺序无放回随机选位（`generateSingleButterPosition` 每次传入已选的 pendingButterSpawns 作 reserved），未能放置的请求保留为 debt。`pendingButterPlacementDebt` 最终总是被设置为剩余请求数（已修复"全部满足时未清零"的 bug）。

**搜索端**（searchRules.resolveGhostBoundaryChanceForState）：
- CAT→MOUSE 且（有 ghost **或** debt>0）时**绝不返回 null** → simulator 绝不 fallback 到 `rules.endTurn`（Math.random）。
- 处理三种情况：
  - candidates=0 → 单一确定性 outcome：`pendingButterPlacementDebt = totalRequests`（无隐藏随机）；
  - totalRequests > candidates → 所有 N 个候选被使用 + 剩余 k−N 保留 debt → 单一确定性 outcome（唯一 ghost 集合，无 k! 伪分支）；
  - totalRequests ≤ candidates → 枚举 uniform k-subset（weight 1/C(N,k)），与真实 sequential without-replacement 同分布。
- **搜索路径 100% 无 Math.random**：simulator `forceEndTurnIfNeeded` 在 ghost/debt 存在时强制走 CHANCE builder（缺失 builder 或返回空 → 抛错，绝不静默 fallback）。

**pickup CHANCE candidate=0**（searchRules.buildButterChanceForState / simulator.defaultBuildButterChance）：返回 debt+1 的确定性 outcome（不是 null），REAL 与 SEARCH 最终 state 一致（§8）。
