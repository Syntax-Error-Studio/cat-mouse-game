## 2. Optimization selection (spec 4) — NOT chosen by win rate

Implemented a single numerically-equivalent optimized implementation based on code-profiling only (the dense 808×128 forward was the hot spot):
- weights flattened into contiguous `Float64Array` buffers (no 2D deref)
- preallocated hidden/feature/nonzero scratch buffers (no per-call allocation)
- **sparse first-layer accumulation**: features are ~40-60 nonzero of 808, so layer-1 = nonzero×128 MACs instead of 808×128
- No quantization / pruning / tanh approximation / weight change. Math identical.

Selection criterion was numerical parity + latency ONLY (never run full-game A/B to pick an implementation).

- NO_TRAP → trap_ch(0,0) quirk preserved.
