## 2. Clean evaluator comparison status (section 2)

- `VALUENET_VS_EVALUATOR` = **NOT_APPLES_TO_APPLES**
- `CLEAN_EVALUATOR_BASELINE` = **UNAVAILABLE_FOR_EXISTING_1K**
- Reason (proven, no guessing): the 145-byte REC stores only `blockedTunnelsCount` (a count) at offset 20 and has **no** field for `tunnelExitChoices`; the actual blocked-tunnel positions are not encoded. Therefore the full `GameEngineState` required by `evaluateForCat` cannot be losslessly reconstructed from the binary, so `evaluateForCat` cannot be recomputed on the re-split 1351 clean held-out states.
- Consequence: the G0.4A-1 numbers `clean ValueNet AUC = 0.519` and `evalForCat AUC = 0.596` came from **different** held-out splits (the eval sidecar aligns only with the *original* `heldout.bin`, which the re-split redistributes). The `0.519 < 0.596` ordering is **not** a valid head-to-head result.
- The `evaluateForCat` raw score IS already emitted per held-out state by the bridge into `heldout_eval.bin` (computed on the authoritative live GameEngineState; the old decodeState path was removed as lossy), but `decodeState` is itself lossy for blocked tunnels, and the sidecar exists only for the held-out shard - not train/val - so it cannot be realigned to an arbitrary re-split either.
- Section 14 (below) fixes this for *future* data by emitting a per-shard `evaluateForCat` sidecar for **every** state; the existing 1k is left as-is (UNAVAILABLE).

## 11. Policy identity is NOT a production solution (section 11)

Even if STATE_PLUS_POLICY proves strong, it only demonstrates that the current target depends on the *generating* policy. The eventual goal is to learn `V_pi(s)` under one clear, gradually-strengthening self-play policy - not `V_mixture(s)`. A target dataset with a canonical/iterative self-play policy is required (see section 13).

## 14. Future bridge must emit clean evaluator sidecar (section 14)

- Implemented in `ai-training/ts-bridge/selfplay.ts`: the generation loop now writes a per-shard `evaluateForCat` sidecar (`train_eval.bin` / `val_eval.bin` / `heldout_eval.bin`, float32 LE, 1:1 with each shard) for **every** state - not just held-out.
