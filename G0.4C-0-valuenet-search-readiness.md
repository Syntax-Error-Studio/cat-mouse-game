## 5. Trap encoding quirk — VERIFIED (spec 5)

- `encodeState` writes `trapPresent` gate at byte 25, but `build_tensors`
  computes `trap_ch = (board==2) | scatter(trapR, trapC)` with **NO trapPresent
  gate** (trapR/trapC default to 0 when no trap).
- **VERIFIED on the 10k binary**: NO_TRAP records = **22,034** (matches external
  audit), actual trap at (0,0) = **0**. And a no-trap record's tensor DOES get
  `trap_ch[0,0]=1` (confirmed on record 0).
- **Decision A**: offline TS inference MUST preserve this quirk for checkpoint
  compatibility (implemented — `buildStateFeatures`/`buildFeaturesFromRecord`
  scatter trapR/trapC unconditionally, exactly like Python).
- **Decision B**: a `REPRESENTATION_V2` (gate trap_ch on trapPresent) is the
  correct long-term fix but requires retraining — out of scope; flagged.
- REPRESENTATION_QUIRK = **PRESENT**

## 12. Search value-domain contract (spec 12)

Real review of `expectiminimax.ts`:
- **MATE_SCORE = 1_000_000**; terminal values `±MATE_SCORE`.
- **`mate` classification is the PRIMARY ordering key** (`mateRank`: cat-mate(2) >
  non-mate(1) > mouse-mate(0)); numeric `value` only breaks ties WITHIN a mate
  category. A non-mate leaf (even ~999,999) can NEVER outrank a genuine forced
  mate, and a ValueNet [-1,+1] leaf (mate=null) slots in identically.
- Leaf evaluation returns a plain number wrapped as `{value, mate:null}` — a
  ValueNet output is structurally identical to an evaluateForCat output.
- Alpha/beta bounds (`ScoreBound`) carry the full (value, mate) lexicographic
  score, so comparisons are scale-robust across evaluators.
- CHANCE nodes: expectation is summed over outcomes; a [-1,+1] ValueNet value
  sums fine. Mate classification at CHANCE nodes collapses to `null` unless ALL
  outcomes are the same-side mate — unaffected by leaf scale.
- **What relies on ORDERING (scale-robust):** mate precedence, alpha/beta
  comparisons, rootActions ranking, within-category tie-break.
- **What depends on ABSOLUTE SCALE:** the displayed `rootValue` magnitude in the
  debug panel; the refutation sidecar's `baselineValue` tie-break offset
  (`refuted ? baselineValue − 1e9 : baselineValue`) — but this only compares
  same-evaluator candidate values, so it stays internally consistent.
- **Refutation sidecar**: uses its OWN exact local geometry checks (validated
  route intercept + win-threat gate), NOT the leaf evaluator — so its exact
  semantics are unaffected by which leaf evaluator is used.

## 13. V_pi vs Search semantic mismatch — FORMAL RISK (spec 13)

- ValueNet learns **V_pi(s)** under the FIXED canonical joint policy pi =
  (hard cat, greedy mouse) — an ON-POLICY value of the terminal outcome.
- Expectiminimax search evaluates **counterfactual / off-policy / adversarial
  mouse branches**: it does NOT assume the greedy-mouse continuation. Its
  minimax semantics maximize the cat's worst-case value under a mouse that can
  be adversarial, not the expected value under the training mouse.
- Therefore **ON-POLICY_AUC = 0.756 does not by itself prove SEARCH_LEAF_QUALITY**.
  A leaf that ranks on-policy outcomes well can still misorder the adversarial
  branches the search explores. This is the central residual risk for C1; the
  offline A/B (paired maps, matched mouse RNG) is the required test.
