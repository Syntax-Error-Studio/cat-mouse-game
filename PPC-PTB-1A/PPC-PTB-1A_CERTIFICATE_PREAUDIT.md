## 0. 一句话结论

**推荐方向成立，但推荐的那条判定式不成立。**

`mouseHasButter && carryingHoleDist <= mouseMovesLeft` 在默认地图上**会把踩陷阱的路线判成必胜**——实测 22 例假证明。
把它改成「携带图 + 移除陷阱格 + 以地形而非配置矩形认洞」之后，鼠方证书在该回合内**可证明是精确的**（400/400 与真实引擎一致），且成本只有一次 H1 评估的 **12%**。

但更要紧的是第二个发现：**在 100ms 预算下，猫方证书根本没有可以触发的叶子**——权威 100ms 车道 20/20 只完成 D1，而 D1 的全部叶子（冻结数据 453/453、本次复算 1044/1044）都是**鼠方回合**。因此「猫一步能抓就判胜」这一半在现有预算里是**空转**。

## 1. 六个问题的直答

### ① 直接使用 BFS 距离作为必胜证书安全吗？

**不安全，而且两个方向的错误性质相反。**

| 方向 | 判定式 | 性质 | 原因 |
|---|---|---|---|
| 鼠 | `carryingHoleDist <= mouseMovesLeft` | **不可靠（会误判为胜）** | 该 BFS 允许走进陷阱格，但引擎里踩陷阱＝剩余步数清零、本回合结束 |
| 猫 | `catWalkDist <= catMovesLeft` | **可靠但不完备** | walk-only 图不含推箱；推箱可以更短，但绝不会更长 |

鼠方这一侧是**硬错误**：它会输出「已证明必胜」而实际不能赢。这不是精度问题，是可靠性问题。

### ② 找到了哪些真实规则反例？

在默认地图上对所有「鼠在洞附近 + 陷阱在更靠近洞的格子上」的组合做穷举，**123 个候选状态里证书报「已证必胜」137 次，其中 22 次引擎判定为「本回合赢不了」**。全部 22 例都是同一机制：陷阱切断了通往鼠洞的路。

最小可读反例（探针自动搜出来的，不是手挑的）：
鼠在 (3,9) 带黄油、剩 4 步，陷阱在 (4,9)；携带图算出到洞 4 步 → 证书报必胜；真实引擎枚举 32 个节点，**无一条合法路线能在本回合入洞**（要么绕远超过 4 步，要么踩陷阱直接结束回合）。

另有四类**不是**反例、但值得钉住的边界：

- **猫占住走廊**：距离图已经把猫格排除，证书正确地**不**触发（实测 dist 从 4 跳到 22）。
- **箱子/固定障碍**：同上，图谱本身就绕开。
- **不是鼠方回合**：`mouseMovesLeft` 此时为 0，门先拦住。
- **鼠没带油**：门先拦住，不会退化成「距离够就算赢」。

还有第六类，是我自己写的第一版修正证书踩到的坑：**配置矩形与地形不一致**。引擎判胜用的是 `targetCell.type === 'mouse_hole'`，而评价器/RULE-B/携带图都用 `config.mouseHole` 矩形。手工地图上两者可以分叉——把矩形内某格改成空地后，第一版证书仍然报必胜，引擎不认。**证书必须以棋盘地形认洞，不能信配置矩形。**

### ③ 低成本合法路线证书是否可行？

**可行，且鼠方这一侧能做成精确判定，不只是「充分条件」。**

精确性来自一个很强的结构事实：**鼠在自己的回合内是唯一会动的对象**。地形、箱子、陷阱位置、猫的位置、携带状态在整个回合内全部不变，携带状态下又不许进传送通道。于是「鼠到洞的最短路」在一张**静态图**上，`dist <= movesLeft` 既是充分也是必要。

改动只有三处：

1. 图里删掉陷阱格（踩上去＝回合结束，不可能赢）；
2. 以棋盘 `mouse_hole` 地形为洞目标（不是配置矩形）；
3. 先过四道门（阶段 / 行动方 / 剩余步数 / 携带），再看距离。

实测 **400/400 与真实引擎判定一致，0 分歧，62 次证成全部能重放出真实引擎的获胜动作序列**。

### ④ 在现有真实猫鼠搜索叶中会触发多少次？

**鼠方：会触发，但只在两种极端的根上；猫方：0 次。**

7 个冻结真实根、按 D1 名义深度展开：

| 根 | 叶子 | 鼠方叶 | 猫方叶 | 证成 | 是否能区分该根的不同猫着法 |
|---|---|---|---|---|---|
| G1T8_first_prodBad | 121 | 121 | 0 | 0 | — |
| G1T9_chance_mixed | 166 | 166 | 0 | 0 | — |
| G2T7_chance_mixed | 187 | 187 | 0 | 0 | — |
| G2T8_critical_refuted | 219 | 219 | 0 | **219（全部）** | 否 |
| G5T3_critical_refuted | 138 | 138 | 0 | 0 | — |

### ⑤ 增加的实际 CPU 成本是多少？

单线程、热态、本机实测（`PPC-PTB-1A/out/p4_cost.json`）：

| 路径 | 每次耗时 | 相对 H1 |
|---|---|---|
| 四道门（只做分支判断） | 0.00006 ms | 0.06% |
| 复用 H1 已算好的 `carryHoleMap` 查表 | 0.00007 ms | 0.07% |
| 单独跑一次携带 BFS | 0.025 ms | 24.5% |
| 完整 `createEvaluationContext` | 0.144 ms | 141% |
| 修正后的证书（含陷阱的三门 BFS） | 0.013 ms | 12.4% |
| H1 单次评估 | 0.102 ms | 100% |

要点：**不要重新跑 BFS**。`carryHoleMap` 在每次 H1 评估里已经算好了（多源反向 BFS，携带图无向，所以「洞→格」的距离就等于「格→洞」），查表是 O(1)。只有当距离门通过、需要判陷阱是否切断时，才重建一次带陷阱的三门 BFS，而这个分支本来就少。

「零新增搜索节点」不等于「零成本」：若按最朴素的写法每次叶子重跑一次携带 BFS，等于给每个叶子加 24% 的评估开销；每 100ms 内叶子数是千级，这一项必须显式记账。

### ⑥ 是否值得进入下一轮独立、feature-flagged M1 原型？

**值得，但要改目标：做成「值标注 + 诊断」，不许在本轮变成 mate 注入。**

理由：

- 鼠方证书**已证明精确**，成本 12%，没有理由不做；
- 但它在这 7 个根上**不改变着法**，所以任何「胜率提升」的预告都是无根据的；
- 想在 100ms 内真正吃到收益，必须先让 **D2 可完成**（预注册 M3 的 PVS/aspiration/TT 跨回合），因为只有 D2 的叶子才是猫方回合，猫方证书才有意义。**顺序应当是 M3 先于 M1 的猫方部分**——这一点与 PPC-ARIMAA-01 原来的 M1→M2→M3 顺序相反。

## 4. P2 三值接口与安全定义

```
PROVEN_SAME_TURN_WIN : 存在完整合法行动见证，当前回合内直接终局获胜
NOT_PROVEN           : 本检测器没找到证明（≠ 不存在）
UNKNOWN              : 预算不足 / 状态不完整 / 随机分支无法确认 / 布局不自洽
```

### 4.1 鼠方（可做成精确）

```
PROVEN  iff  phase == Playing
        &&  currentPlayer == Mouse
        &&  mouseMovesLeft > 0
        &&  mouseHasButter
        &&  trapAwareCarryingDist(mouse, boardHoleCells) <= mouseMovesLeft
```

精确性论证（四条前提，缺一不可）：

1. **单动作者**：鼠回合内只有鼠移动，猫不动、箱子不动、地形不动 → 图在整回合内静态。
2. **携带不变**：只有 `mouseSkill` 会消耗黄油，而用技能就拿不到本回合胜利 → 携带状态在胜利线上恒定。
3. **通道排除**：携带状态禁止进传送通道，携带图已经不含 Tunnel 格。
4. **陷阱排除**：踩陷阱＝剩余步数清零＋回合结束，因此陷阱格必须从图中删除。

在这四条下，`dist <= movesLeft` 是充要条件。**但注意前提 1 只在「鼠自己的回合内」成立**；跨回合就不成立了，不能外推。

洞目标必须取 `board[r][c].type === 'mouse_hole'` 的格子集合。若该集合为空或与 `config.mouseHole` 矩形不一致，返回 **UNKNOWN**（失败关闭），不要退回矩形。

### 4.2 猫方（只能做充分条件）

```
PROVEN  ⟸  phase == Playing && currentPlayer == Cat && catMovesLeft > 0
        &&  catWalkDist(mouse) <= catMovesLeft
```

`catWalkDist` 的每条边都是引擎合法步，所以这条路真实可执行 → 必然能抓。但 walk-only 图**不含推箱**，所以真实最短步数可能更小；`catWalkDist > catMovesLeft` **不能**推出「抓不到」。因此猫方永远不能输出「已证明不赢」。

### 4.3 CHANCE 语义（必须写清，否则会被误读为概率 1）

本项目里「概率 1 必胜」这句话有两层，不能混：

- **鼠方证书不产生机会节点**。鼠回合内唯一的随机是吃掉黄油后公告一个新幽灵位置，而幽灵是**非阻挡**标记（`pendingButterSpawns` 在移动判定里不参与阻挡），因此不论公告落在哪，鼠的入洞路线不变 → 「所有正概率结果均获胜」平凡成立，**但这不是「计算了概率」，是「随机项与结论无关」**。
- **猫方证书就更干净**：猫回合内没有任何机会节点。
- 反过来说：**任何跨越 CAT→MOUSE 边界的结论都必须重新论证**，因为 `enumerateGhostBoundaryOutcomes` 会在那里展开真正的机会节点，而实体化的黄油**会挡住猫**。这正是「鼠方证书不能外推到下一回合、猫方证书不能跨边界」的原因。

### 4.4 mate 准入：本轮明确不具备

把证书注入正式叶子值需要另外四份合同，本轮**一份都没做**：

| 合同 | 状态 | 缺口 |
|---|---|---|
| mate-distance | ⛔ 未做 | 证书只给「本回合可赢」，不给距离；`±MATE_SCORE - d` 的 d 无定义 |
| 搜索深度 | ⛔ 未做 | 证书在 depth 0 叶子触发，但值属于「更深的层」，会破坏按深度分层的 TT 语义 |
| TT EXACT | ⛔ 未做 | 若把证书值按 EXACT 存，会在不同 `catMovesLeft` 的同 key 状态间串味；`stateKey` 不含规则版本 |
| 随机分支 | ⛔ 未做 | 见 4.3，跨边界必须走机会节点 |

**结论：本轮及下一轮原型都不许把证书写进叶子值。** 允许的用途只有两个：搜索返回值的**标注**（mate-in-1 报告给 UI/日志）和离线诊断。

### 4.5 现成的反例：H1 对「已判定」的局面给的是普通分数

`PPC-PTB-1A/out/p3_h1_blindness.json`：一个鼠下一手必胜的叶子（`carryHoleDist = 1`，剩 2 步，引擎真值 `win = true`），H1 给猫的值是 **-2094.05**，而 mate 量级是 1e6。差三个数量级。这既说明证书确实带来了 H1 没有的信息，也说明**不能直接把 -2094 当成「快输了」来比较**。

## 5. P3 独立正确性比较方法与结果

**真值定义**（不使用任何 AI 代码）：对给定状态，用**真实引擎转移**（`mouseMove` / `catMove`）穷举当前行动方本回合内的全部合法动作序列，判定是否可达终局。

三条硬约束：

- 鼠方 DFS 不展开 `mouseSkill`（消耗黄油，必然放弃胜利）与传送（携带禁入），因此搜索空间就是真实胜利空间；
- 猫方 DFS 不展开 `catPlaceTrap`（不移动猫，抓不到）；
- 每个「证成」都要**重放**：把证书给出的动作序列喂回真实引擎，必须真的变成 `MouseWins`。

| 检验 | 规模 | 结果 |
|---|---|---|
| 朴素鼠方证书 | 123 候选 / 137 次触发 | **22 假证明**，14 正控全部为真 |
| 修正鼠方证书 | 400 状态 | **400/400 一致，0 分歧，0 重放失败**，62 次证成 |
| 猫方证书（可靠性） | 3011 状态 / 1929 次触发 | **0 假证明** |
| 猫方证书（完备性·邻域带） | d = k+1 的 400 个状态 | 0 漏检 |
| 猫方证书（完备性·推箱独有） | 304 个走路不可达候选 | 0 例真能推箱抓到 |
| 真实引擎 vs 搜索模拟器 | 40 个假证明样本（唯一存在争议的一类） | **0 分歧**（`REAL_ENGINE_WITNESS_PARITY = PASS`） |

关于猫方「不完备」要说实话：**理论上一定不完备**（推箱可以在走路图上不可达时仍抓到），但在这张默认地图 + 这个采样带里**一例都没出现**。所以正确表述是「结构上不完备，实证未观测到」，不是「不完备已被测量」。

## 6. P4 覆盖率与成本的解读

### 6.1 为什么猫方证书是空转

搜索的深度以「行动权变化」为单位递减。D1 的含义是：**猫自己的整个回合被展开，之后立刻静态评估**。因此 D1 的叶子必然是**鼠方回合**。这与冻结数据完全一致（depth 1：453 mouse / 0 cat），本次独立复算也一致（1044/1044）。

D2 才会出现猫方叶子（冻结 depth 2：68412 cat / 453 mouse），但 D2 的固定深度墙钟是 1.4s 量级，100ms 内完成 0 次。**所以「猫一步能抓就判胜」在现有预算里没有任何触发点。**

这条否证同时说明：PPC-ARIMAA-01 把 M1 的动机主要写成「猫方立即抓捕证书」是**用错了半边**。真正能用的是鼠方那一半，而它恰恰是原始的 if 写法里不可靠的那一半。

### 6.2 为什么「322 次触发」仍然不构成棋力论证

G2T8 与 G6T3 两个根上**全部叶子都证成**；其余五个根**一个都不证成**。证书在这 7 个根上从没把「好着法」和「坏着法」分开过——它只是把一个已经全输的局面全部标成输。

因此：

- 它能改善**报告**（把「H1 认为 -27」变成「已判定本回合必失」）；
- 它**不能**改善**选择**；
- 任何「胜率提升」的说法必须先拿出一个「部分叶子证成」的根。

### 6.3 成本记账

不要只报「新增节点 = 0」。真实开销取决于实现方式：

- 复用 `carryHoleMap` 查表：0.00007ms / 叶子，可忽略；
- 每次重跑携带 BFS：0.025ms / 叶子 = H1 的 24.5%，千级叶子就是 25ms——**半个预算**；
- 带陷阱的三门 BFS（仅在距离门通过时）：0.013ms / 叶子 = H1 的 12.4%。

**所以「零节点」必须改写成「零节点 + 一次表查询；仅在门通过时一次小额 BFS」。**
